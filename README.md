# Сайт SalfVisuals

Статический сайт: `index.html` + `style.css` + `script.js` + `version.json` +
`sf_logo.png`. Никакого сервера не нужно для самого сайта — просто набор
файлов, **все в одной папке, без вложенных подпапок** (GitHub через
веб-интерфейс не всегда нормально принимает загрузку целых папок — проще,
когда всё лежит плоско в корне репозитория).

## Важно — что тебе нужно сделать самому

**У меня нет реального собранного `.jar` файла мода** — я всё это время присылал
тебе только исходный код, который ты сам собирал через `gradlew build`.
Чтобы кнопка "Скачать" на сайте реально работала:

1. Собери мод у себя (`gradlew clean build`, как мы уже делали)
2. Возьми файл `build/libs/salfvisuals-0.1.0.jar`
3. Переименуй в `salfvisuals-0.1.0-beta.jar` (или поправь имя в `version.json`, см. ниже)
4. Залей его **прямо в корень репозитория**, рядом с `index.html` — никаких
   подпапок типа `downloads/`, просто файл рядом со всеми остальными

Без этого шага кнопка будет вести в никуда.

## Как проверить локально

Открывать `index.html` двойным кликом **не сработает** — браузер блокирует
`fetch()` для локальных файлов (`file://`). Нужен простой локальный сервер:

```
cd site
python -m http.server 8000
```

Потом открой `http://localhost:8000` в браузере.

## Как выложить в интернет (бесплатно) — GitHub Pages

1. Создай репозиторий на GitHub и залей туда **содержимое** этой папки —
   каждый файл (`index.html`, `style.css`, `script.js`, `version.json`,
   `sf_logo.png`, собранный `.jar`) по отдельности прямо в корень репозитория,
   не саму папку целиком (иначе всё окажется на уровень глубже, и GitHub
   Pages не найдёт `index.html` в корне — сайт просто не откроется).
2. В настройках репозитория — `Settings → Pages → Source: main branch`
3. Через пару минут сайт будет доступен по адресу вида
   `https://твой-ник.github.io/имя-репозитория/`

Другие бесплатные варианты с тем же принципом — Netlify, Vercel, Cloudflare
Pages (перетаскиваешь файлы в их веб-интерфейс так же, без вложенной папки).

## Как выпустить новую версию

Открой `version.json` и поменяй нужные поля:

```json
{
  "version": "0.2.0",
  "stage": "beta",
  "releaseDate": "2026-10-01",
  "jarFile": "salfvisuals-0.2.0-beta.jar",
  "changelog": [
    "Что нового в этой версии",
    "Ещё один пункт"
  ]
}
```

Положи новый `.jar` рядом с остальными файлами (в тот же корень, без папок),
обнови `jarFile` на его имя — весь остальной сайт (шапка, кнопка, чейнджлог)
обновится сам, HTML/CSS трогать не нужно.

Когда решишь выйти из беты — просто смени `"stage": "beta"` на `"stage": "release"`.

## Счётчик скачиваний (сегодня / за неделю / за всё время)

На сайте есть блок с живой статистикой скачиваний под кнопкой "Скачать" —
он спрятан (`hidden`), пока не настроен, и появляется сам, как только всё
подключено.

Данные считает отдельный маленький сервис —
`salfvisuals-downloads-backend` (Node.js, см. его собственный README —
там же готовый способ раздачи файла с подсчётом, чтобы цифры были настоящими,
а не накручиваемой кнопкой на фронте). Его нужно задеплоить отдельно
(любой сервер/VPS, куда уже смотрит `backend-example` для Presence — подойдёт
тот же).

Как подключить к сайту:

1. Задеплой `salfvisuals-downloads-backend`, получи его адрес (например
   `https://твой-домен:28452`).
2. В `version.json` впиши этот адрес в поле `downloadBaseUrl` (без слеша в
   конце).
3. Всё остальное сайт сделает сам: кнопка "Скачать" начнёт вести через
   `downloadBaseUrl/download/<jarFile>` (бэкенд посчитает и отдаст файл), а
   блок статистики подтянет цифры с `downloadBaseUrl/api/stats` и покажет
   себя.

Пока `downloadBaseUrl` пустой (или бэкенд недоступен) — кнопка работает как
раньше, прямой ссылкой на `.jar`, без счётчика, а блок статистики просто не
показывается — никаких нулей или выдуманных цифр на сайте.
